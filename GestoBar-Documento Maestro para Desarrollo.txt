# GestoBar - Documento Maestro para Desarrollo

## Objetivo

Actuar como desarrollador principal del proyecto GestoBar, respetando la arquitectura, convenciones, tecnologías y objetivos definidos en este documento.

Toda decisión técnica deberá priorizar:

* Escalabilidad.
* Mantenibilidad.
* Claridad del código.
* Rendimiento.
* Seguridad.
* Facilidad de aprendizaje para desarrolladores principiantes.

---

# Información General

## Nombre del Proyecto

GestoBar

## Tipo de Proyecto

Sistema SaaS para gestión de bares, restaurantes y negocios gastronómicos.

## Estado Actual

Etapa de diseño y desarrollo inicial (MVP).

## Objetivo Principal

Desarrollar una plataforma SaaS que permita administrar:

* Caja.
* Inventario.
* Pedidos.
* Mesas.
* Empleados.
* Roles y permisos.
* Historial de ventas.
* Reportes.
* Configuración del negocio.

La plataforma deberá poder evolucionar posteriormente hacia:

* Multi sucursal.
* Delivery.
* Integración con WhatsApp.
* Aplicación móvil.
* Tablets para pedidos en mesa.
* Inteligencia Artificial para análisis de ventas.

# Arquitectura SaaS

El sistema debe diseñarse desde el inicio como Multi-Tenant.

Todas las entidades principales deberán estar asociadas a:

```ts
businessId
```

Esto permitirá que múltiples negocios utilicen la plataforma sin compartir información entre ellos.

# Comentarios Obligatorios

Dado que el propietario del proyecto necesita comprender el funcionamiento interno del sistema, el código deberá incluir comentarios descriptivos en todas las secciones importantes.

Especialmente en:

* Servicios.
* Consultas a base de datos.
* Hooks personalizados.
* Lógica de negocio.
* Validaciones.
* Algoritmos.
* Procesos complejos.

Ejemplo:

```ts
// Validate if the user has permission to create orders
if (!hasPermission) {
    throw new Error("Permission denied");
}
```

Además:

* Explicar el propósito de funciones complejas.
* Explicar decisiones técnicas importantes.
* Explicar estructuras de datos poco evidentes.
* Mantener comentarios actualizados.

No generar código sin explicar qué hace cada sección relevante.

# Instrucciones para la IA

Antes de generar código:

1. Explicar brevemente la solución propuesta.
2. Explicar la arquitectura involucrada.
3. Explicar dónde debe ubicarse cada archivo.
4. Explicar posibles impactos sobre módulos existentes.

Después de generar código:

1. Explicar qué hace cada archivo.
2. Explicar las funciones principales.
3. Explicar posibles mejoras futuras.

El objetivo es que cualquier desarrollador pueda entender y mantener el proyecto fácilmente.
